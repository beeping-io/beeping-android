## Tool

[`gitleaks`](https://github.com/gitleaks/gitleaks) (Homebrew install).

## Initial scan — findings

Working tree + full git history (`--log-opts="--all"`).

```bash
gitleaks detect --source . --no-banner --log-opts="--all"
```

```text
47 commits scanned.

WRN leaks found: 2
```

Two hits to the `generic-api-key` rule, both in
`AndroidBeepingCore/src/test/java/com/beeping/AndroidBeepingCore/BeepingTimberTreeTest.kt`
at lines 80–81, in commits `e03e853` (release of v0.0.0) and `97b72e31`
(original BEE-60 feature commit).

## Risk assessment — false positive

Inspection of the offending lines shows the "secret" is an **intentional
test fixture**:

```kotlin
@Test
fun `redact masks apiKey query param`() {
    val input = "GET /v1/health?apiKey=bk_LFhY0ZQnuYL1Pg"
    val redacted = BeepingTimberTree.redact(input)
    assertEquals("GET /v1/health?apiKey=***", redacted)
}
```

`bk_LFhY0ZQnuYL1Pg` is a 17-character placeholder string that lives only
in this unit test. Its purpose is to verify that the `BeepingTimberTree`
log redactor masks API-key-shaped values before they reach any sink. It
is not a registered Firestore document, never had any access to any
endpoint, and is shorter (17 chars) than the real key format (25+ chars).

Verified out-of-band: the string is **not** referenced anywhere else in
the codebase — only inside this test file.

## Mitigation — gitleaks config

A `.gitleaks.toml` allowlist was added at the repo root pinning the path
of this single test file. Adding more test fixtures elsewhere should NOT
expand the allowlist — the burden of proof stays on the test.

```toml
[extend]
useDefault = true

[allowlist]
description = "Intentional API-key-shaped fixtures for redaction unit tests"
paths = [
  '''AndroidBeepingCore/src/test/java/com/beeping/AndroidBeepingCore/BeepingTimberTreeTest\.kt''',
]
```

## Post-config verification

```bash
gitleaks detect --source . --no-banner --config .gitleaks.toml --log-opts="--all"
```

```text
47 commits scanned.
scanned ~935123 bytes (935.12 KB) in ~160ms
INF no leaks found
```

**Result: 0 leaks.** Repo is clean for the public visibility flip.

## Cadence

Re-run gitleaks before any major release or whenever a new branch is
merged that touches `docs/`, configuration, CI or build scripts. A CI
gitleaks job is a sensible follow-up (out of scope for this PR; capture
under the cross-repo CI hardening pass tracked alongside BEE-2274).
